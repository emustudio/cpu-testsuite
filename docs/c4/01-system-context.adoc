= Level 1 — System Context

The *CPU Test Suite* is a declarative, generative unit-testing framework. A *CPU plug-in
developer* uses it to describe how a single CPU instruction should behave and lets the
framework generate and execute a large number of test cases against the real CPU plug-in.

== Actors and external systems

[cols="1,3",options="header"]
|===
| Element | Responsibility

| *CPU Plug-in Developer*
| Author of the CPU plug-in. Writes a small, declarative test specification per instruction
  (or instruction family) and chooses which operand combinations to generate.

| *CPU Test Suite* (this system)
| Provides the fluent specification API, generates operand combinations, prepares the CPU
  environment, single-steps the instruction and verifies registers, flags and memory.

| *CPU Plug-in under Test*
| The subject under test. A concrete emuStudio CPU (for example Intel 8080 or Z80) that
  implements the emuLib `CPU` interface and exposes registers, flags and memory access.

| *emuLib*
| Shared emuStudio plug-in API and runtime helpers. The suite depends on `CPU`,
  `MemoryContext` and `NumberUtils`; the CPU plug-in implements the same API.

| *JUnit 4*
| Executes the developer's test classes and provides the assertion primitives
  (`org.junit.Assert`) used internally by the suite's verifiers.

| *Build Tool (Gradle / Maven)*
| Resolves `net.emustudio:cpu-testsuite_<emuLibMajor>` as a `test` dependency and runs the
  test task in which the suite operates.
|===

== Key scenario

. The developer describes an instruction with a fluent `TestBuilder` (operands, expected
  result, expected flags).
. The developer asks a `Generator` method to produce operand combinations (exhaustive
  `forAll*` or random `forSome*`).
. For every generated pair the suite prepares the CPU, executes one step and verifies the
  outcome, failing the JUnit test on the first mismatch.
