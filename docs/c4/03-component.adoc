= Level 3 — Components

This level opens up the *CPU Test Suite Library* container and shows its internal building
blocks and how a test flows through them. The components map directly onto the Java
packages under `net.emustudio.cpu.testsuite`.

== Components

[cols="1,3",options="header"]
|===
| Component | Responsibility

| *Generator* (`Generator`)
| Static utility that produces operand data and drives the test. `forAll*` methods iterate
  every combination (exhaustive); `forSome*` methods use a configurable random subset
  (`setRandomTestsCount`). Supports 8-bit / 16-bit, unary / binary, equal-operands and
  predicate-filtered variants.

| *TestBuilder* (`TestBuilder`, abstract)
| The fluent, declarative specification. Chained calls describe where operands come from,
  what result to expect and which flags to check. It translates the specification into
  concrete injectors and verifiers registered on a `TestRunner`. Consumers use the
  `ByteTestBuilder` / `IntegerTestBuilder` subclasses.

| *TestRunner* (`TestRunner`, `BiConsumer<TOperand,TOperand>`)
| The execution engine. For each operand pair it resets the CPU, restores preserved flags,
  runs all injectors, snapshots a `RunnerContext`, single-steps the CPU and runs all
  verifiers. Supports keeping/clearing injectors and verifiers between runs.

| *RunnerContext* (`RunnerContext`, immutable)
| Value object passed to injectors and verifiers. Holds both operands and the CPU state
  (flags, PC, SP, registers) captured just before the step, so verifiers can compute the
  expected result.

| *CpuRunner* (`CpuRunner<TCpu>`, abstract)
| Adapter that wraps the CPU and a memory stub and exposes a uniform control surface:
  `reset`, `setProgram`, `setByte`, `step`, register/flag accessors. Implemented per CPU.

| *CpuVerifier* (`CpuVerifier`, abstract)
| Adapter for assertions. Provides `checkMemoryByte` / `checkMemoryTwoBytes`; consumers add
  `checkFlags` / `checkNotFlags`. Uses JUnit assertions under the hood.

| *FlagsCheck* (`FlagsCheck`, abstract)
| Fluent, per-CPU description of which flags should be set/cleared, optionally conditioned
  on operands and result via `expectFlagOnlyWhen`.

| *Injectors* (`injectors` package)
| Building blocks that prepare CPU state before the step. Instruction injectors
  (`NoOperInstr`, `OneOperInstr`, `TwoOperInstr`) assemble opcodes and operands into a
  program via `DefaultProgramGenerator`; memory injectors (`MemoryByte`, `MemoryWord`,
  `MemoryAddress`, `MemoryExpand`) seed data memory. `TwoOperInjector` is the SPI.

| *Verifiers* (`verifiers` package)
| Building blocks that check state after the step: `FlagsVerifier` (expected flags from a
  `FlagsCheck` and an operation), `MemoryByteVerifier` and `MemoryWordVerifier` (expected
  value at a computed address).

| *Memory Stubs* (`memory` package)
| In-memory `MemoryContext` implementations acting as the CPU's memory during tests.
  `MemoryStub` is the SPI; `ByteMemoryStub` and `ShortMemoryStub` differ in cell width and
  honour a little-endian word-reading strategy.
|===
